## Current decisions

### Hero concept (decided)
- Retain the original concept: dark background, personal introduction, availability status, role, supporting text, two actions and the animated code editor.
- **Supersedes** the text only v4 hero direction and any other experimental hero guidance. Do not propose another hero concept.

Supporting paragraph: "I help turn your idea into a product people enjoy using, built to grow with your business." It fits one line on a 1512px desktop (max width 48rem), wraps naturally on mobile, and is never forced to nowrap. Font sizes were not increased.
- Availability: small bordered pill, static emerald dot, text "Open to new projects". No pulsing or blinking, no large badge.

### Code editor
- Decorative only. It does not execute code, so there is no LIVE badge.
- Header: window dots, file name (centre), framework label (right). The language is implied by the file extension and is not repeated.
- A full sample is visible from the first paint. Rotation types the next sample in row by row, replacing one line at a time, and never clears the panel.
- Every sample has exactly 8 lines, so the height never shifts.
- Reduced motion: no rotation, no typing, static caret.
- Desktop maximum width is 896px (`max-w-4xl`), with the page gutters on smaller screens. Hidden below 550px.
- The editor lives in `components/HeroEditor.tsx` with its own state. No backdrop blur over the animated canvas.

### Buttons (global)
- Text action buttons use the shared `.btn-compact` classes in `app/globals.css`, with variants `-primary`, `-ghost`, `-light` and `-indigo`.
- Visible height: 38px (40px when the variant has a 1px border), down from about 56 to 58px originally. Labels are 15px at weight 500, widths are content driven, vertical padding is 8px.
- No transform scaling of whole buttons. Hit area grows to 44px through a `::after` pseudo element, so keep at least 12px between neighbouring buttons.
- Not shrunk: navigation links, form fields, icon controls (for example social icons).
- Hover, pressed, focus-visible (2px periwinkle outline) and disabled states are defined in the shared class.

### Typography
- Headings (h1 to h4) and the hero role use regular DM Sans (`font-heading`, weight 400), loaded with `next/font` in `app/layout.tsx`. Inter stays for body copy and controls. The editor keeps its monospace font.
- Weights: 400 for headings and body copy, 500 at most for controls and small emphasis. No `font-bold` or `font-semibold` anywhere in rendered components. Hierarchy comes from size, spacing and solid colour.

### Performance of decorative motion
- The hero has one Three.js renderer and one loop, created once. Pointer data lives in a ref, never in React state.
- Renderer lifecycle (fixes the "Cannot read properties of null (reading 'precision')" crash): the hero creates its canvas inside the effect, so every effect run, including React Strict Mode's development replay, owns a fresh canvas. Never reuse a canvas after `forceContextLoss()`: the next renderer receives the lost context and Three.js crashes. Construction is wrapped in try/catch and rejects an already lost context; on failure, runtime context loss or a render error, partial resources are released and only the decorative canvas is removed, leaving the CSS background, content, editor and buttons working. No retry loop. Do not disable Strict Mode or patch `node_modules` to hide this.
- The loop and the editor typing pause when the hero is off screen or the tab is hidden (`components/useActive.ts`). Reduced motion draws a single static frame and does not rotate the editor.
- Pixel ratio is capped at 1.5, drawing is limited to 30fps, antialiasing is off. Cleanup cancels the frame, disposes geometry, material and renderer, and releases the context.
- Scroll handlers are passive and throttled to one read per frame. Project screenshots go through `next/image` (they are 3 to 5MB source PNGs). Do not add backdrop blur over animated or large scrolling content.

### Text colour
- No text gradients anywhere. Do not use `bg-clip-text`, `text-transparent` or `-webkit-text-fill-color: transparent`.
- Display name and heading accents use solid periwinkle (`text-indigo-300`). Body headings use white.
- Background gradients, button backgrounds and editor syntax colours remain allowed.

### Punctuation in display copy
- No em dashes, en dashes or hyphens in visible prose. Write "full stack", "cross platform", "ecommerce", or rephrase.
- Keep hyphens in code, URLs, email addresses, package names, CSS classes, identifiers and technical notation.

### Projects carousel (ARCHIVED, superseded by the curated layout above)

- **Supersedes** the earlier showcase with an external caption, Previous, Next and Play or Pause buttons, an "n / 12" counter and "View all projects". Those are gone; the previous version is kept in `components/archive/ProjectsShowcaseCarousel.tsx` (earlier ones: `ProjectsEditorial.tsx`). None are imported.
- Reference: `references/*.mp4` (a testimonial carousel). Its cycle: a settled card with content on the left and an image on the right; the image expands across the SAME card while the content withdraws; the outgoing card shrinks and glides aside; the next card comes forward, its image returns to the right and its content is revealed. Narrower neighbours recede on both sides.
- Each card holds everything: left, name, short description, verified technologies (when known) and "Visit website"; right, the project screenshot (opens the enlarged preview dialog). No category preheader, no caption block beneath. Beneath the stage there are only the 12 navigation dots (accessible names "Show project n of 12: Name", `aria-current` on the active one).
- Composition: one active card (720 x 380 desktop, 560 x 340 tablet, 300 x 500 mobile with the screenshot below the content), two neighbours per side at 0.6 and 0.44 scale, dimmed rather than blurred. Solid card surfaces, thin edge, soft shadow, no rotation, no browser chrome. Stage height is fixed. Screenshots use `object-fit: contain` on a quiet matte, so they are never cropped or stretched.
- Motion: one Web Animations timeline per cycle. The settled hold (about 3000ms) is the only long pause; the moving part is about 1000ms: takeover 0 to 400ms, travel 280 to 940ms (it starts before the takeover has finished), content reveal ending at 1000ms. Decelerating curves (`cubic-bezier(0.3, 0, 0.1, 1)` for travel, `(0.3, 0, 0.15, 1)` for takeover) with a soft landing, no bounce, and no zero speed gap between phases. Do not make every phase longer to fix a rough result.
- Only transforms and opacity are animated, never width, height, left or top. The screenshot layer is always card sized and settles to its side with a uniform scale (identical proportions, nothing stretched); the matte behind it is one flat rectangle scaled from its edge; the content layer only fades. Layers keep their identity (no remounting, no duplicate copies). `will-change` is set only on the moving elements during a cycle. Screenshots are mounted three steps either way so nothing mounts, loads or pops in at a boundary.
- Last to first is one step (ring offsets). Non adjacent dot jumps that would sweep across the stage fade out and in instead. The incoming card passes in front of the outgoing one with a single z-index step.
- Pausing: hover anywhere over the showcase (including mid takeover or mid travel) and keyboard focus inside it pause the whole timeline; leaving resumes from the same point. Also paused when under 60 percent visible, the tab is hidden or the preview dialog is open. Manual selections (dots, neighbour click, swipe) run a short transition without the hold and are not stopped by hover or focus. Reduced motion: no timeline, settled split card, dots select instantly.
- Touch: horizontal swipes change project, vertical scrolling is untouched (`touch-action: pan-y`). Only the active card's content and image button are keyboard reachable; other cards are `inert` or `tabIndex -1`. Manual selection is announced politely; automatic changes are not.
- Verified: the old width animation produced about 0.03 layout shift and 77 Layout events per transition; the transform based version reports no layout shift entries and 19 Layout events (2.5ms) per transition. Headless Chrome here has no GPU compositing, so compositor only playback is not proven by these numbers.
- Order and facts unchanged: GraBoqs, TCG Telegraph, Pharma Medtech, then the rest. Get Valyx Peptides still needs a screenshot.
